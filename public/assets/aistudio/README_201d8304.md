# MIDO OPTICS

Bilingual, responsive storefront for optical and sunglass frames, with a persistent SQLite API, stock-aware checkout, store pickup, prescription details, image upload, and protected administration.

## Requirements

- Node.js 22 or newer and npm.
- A modern browser. Camera access requires `localhost` or HTTPS and user permission.

## Run locally

1. Copy `.env.example` to `.env` and set `ADMIN_TOKEN` to a long private random value.
2. Install dependencies: `npm install`.
3. Initialize the persistent SQLite database: `npm run db:init`.
4. Add the starter catalogue (optional): `npm run db:seed`.
5. Start the API and storefront together: `npm run dev`.
6. Open the Vite URL shown in the terminal (usually `http://localhost:5173`). The API runs at `http://localhost:4000`; uploads and data persist in `./uploads` and `./data`.

For a production build, use `npm run build`, then `npm run start`. The Express server serves the built storefront and API on `PORT` (default 4000). Configure HTTPS at your hosting platform or reverse proxy for camera access outside localhost.

## Environment

| Variable | Purpose | Default |
| --- | --- | --- |
| `PORT` | Express listen port | `4000` |
| `DATABASE_PATH` | SQLite database file | `./data/mido.sqlite` |
| `UPLOAD_DIR` | Uploaded images and prescription files | `./uploads` |
| `ADMIN_TOKEN` | Secret required by admin API | Required for admin use |
| `VITE_API_URL` | Optional API base URL for a separately hosted frontend | same origin |

Never commit `.env`, customer uploads, or the SQLite database. Make regular backups of both the database and uploads directory. Set a unique `ADMIN_TOKEN`; requests to `/api/admin/*` and `/api/upload` require it in `x-admin-token`.

## Structure

```text
src/                 React storefront, bilingual flows, responsive styles
server/index.ts      Express API, validation, uploads and admin endpoints
server/db.ts         SQLite connection and schema initialization
prisma/schema.sql    Versioned initial database schema
server/seed.ts       Optional sample optical/sunglass products and lenses
Dockerfile           Single-container production image
docker-compose.yml   Persistent volumes for database and uploads
```

The SQL schema creates `products`, `variants`, `lenses`, `store_settings`, and `orders`, with foreign keys and stock/price checks. `npm run db:init` safely applies its idempotent initial migration. Extend `prisma/schema.sql` with additive migrations before changing production data.

## Administration

Open the **ADMIN** link in the footer and enter the same secret as `ADMIN_TOKEN`. The dashboard can add products with a colour, hex swatch and comma-separated image URLs, add lenses with details and image URL, adjust prices and stock, publish/unpublish items, change order status, and edit contact details and opening hours. Upload an image through `POST /api/upload` as multipart form data under `image`; the returned `/uploads/...` URL can be used in product variant images or lens image fields. Variants are added with a product; add extra colours through `POST /api/admin/products` or directly in the database.

## Customer flows

- Optical catalog → product/color selection → optional virtual camera preview → lens choice → checkout.
- Sunglass catalog → product/color selection → checkout.
- Checkout stores right/left SPH, CYL and AXIS, customer name and phone, and an optional prescription image. Only store pickup is offered; payment is cash at pickup. There is no online card payment or shipping workflow.
- Order creation validates customer inputs and selected inventory, records the order, and decrements stock. The admin dashboard lists incoming orders and lets staff update their status.

The camera uses the browser's front-facing stream with explicit browser permission and stops it on close. The current frame overlay is an illustrative preview, not facial landmark tracking or a prescription/fit measurement; users can close it and continue normally. Prescription uploads are limited to 8 MB by the upload handler.

## Deploy with Docker

1. Copy `.env.example` to `.env` and set a strong `ADMIN_TOKEN`.
2. Build and start with `docker compose up -d --build`.
3. Put the service behind HTTPS and point the domain to port 4000.
4. Keep the named `mido-data` and `mido-uploads` volumes and include them in backups. Seed sample items before first deployment with `npm run db:seed`, or execute that command in a one-off container with the same persistent volume.

For managed app hosts, attach durable storage for both `DATABASE_PATH` and `UPLOAD_DIR`. Ephemeral filesystems will lose orders or photos after redeploy. SQLite is suitable for a modest single-instance shop; move to a managed PostgreSQL service before scaling to multiple concurrent application instances.

## Main API

`GET /api/health`, `/api/store`, `/api/products?category=prescription|sunglasses&page=1&limit=12`, `/api/products/:slug`, `/api/lenses`, and `POST /api/orders`. Admin endpoints are under `/api/admin` and require the secret header. Responses use JSON; validation errors return 400, unavailable stock returns 409, and missing/invalid admin credentials return 401.

## Production checklist

- Use HTTPS, strong unique admin secret, durable storage and scheduled backups.
- Restrict admin access further at the hosting or identity layer if multiple staff need individual accounts; this starter uses one shared secret.
- Configure an appropriate privacy notice and retention period for prescription files and customer details.
- Add local currency/tax confirmation and business contact details before opening orders.
- Camera permission is optional; the product image and normal checkout remain available if denied.
