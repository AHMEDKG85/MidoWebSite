# ميدو للبصريات

متجر عربي باتجاه RTL لعرض النظارات والعدسات وإتمام الطلبات، مع لوحة إدارة، خادم Express، وقاعدة SQLite. الواجهة تتضمن مشهد نظارة ثلاثي الأبعاد يتحرك مع التمرير، مع احترام إعداد تقليل الحركة في الجهاز.

## التشغيل المحلي

يتطلب Node.js 22 أو أحدث.

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

افتح `http://localhost:3000`. في أول دخول إلى لوحة التحكم (`/admin`) أنشئ كلمة مرور الإدارة إذا تركت `ADMIN_TOKEN` فارغاً. لا توجد كلمة مرور افتراضية. أضف بيانات المحل والمنتجات الحقيقية من اللوحة؛ كتالوج العرض التجريبي غير مفعّل افتراضياً.

## تشغيل الإنتاج عبر Docker

1. انسخ `.env.example` إلى `.env`، ثم عيّن `ADMIN_SESSION_SECRET` ثابتاً وطويلاً.
2. عيّن `APP_URL` إلى عنوان النشر العام. لمزامنة موقع المتجر مع لوحة خدمات Mido، اضبط `EXTERNAL_SYNC_SECRET` بنفس قيمة `MIDO_SYNC_SECRET` في نشر لوحة الخدمات. هذا المفتاح يحمي تعديل محتوى الموقع، مزامنة الكتالوج، وسجل حذف الطلبات.
3. شغّل:

```powershell
docker compose up --build -d
```

تُحفظ قاعدة SQLite والملفات المرفوعة في وحدات Docker الدائمة `mido-data` و`mido-uploads`. احتفظ بنسخة احتياطية منهما قبل أي صيانة أو نقل للخادم. فحص الصحة متاح على `/api/health`.

## الطلبات ولوحة التحكم

- يسجل `POST /api/orders` الطلب في SQLite، ويتحقق من المنتج واللون والسعر والمخزون والعدسة من بيانات الخادم، ويخصم المخزون داخل معاملة واحدة.
- عند توفر API، يعرض المتجر كتالوج الخادم كمصدر وحيد للأسعار والمخزون؛ تعديلات Firebase وحدها لا تصبح قابلة للطلب حتى تُسجل أيضاً عبر لوحة الخادم.
- لكل طلب كود ثابت يمنع إعادة التسجيل عند إعادة المحاولة. الحذف يسجل كوداً محذوفاً حتى لا تعيده مزامنة Firestore.
- إذا لم يصل المتصفح إلى خادم API، تظهر رسالة واضحة ولا يتم إنشاء طلب من أسعار المتصفح. لذلك لا تكفي استضافة ملفات ثابتة وحدها لإتمام الطلبات؛ وجّه النطاق إلى تطبيق Express أو شغّل الواجهة والخادم على النطاق نفسه.
- يمكن وصل لوحة Vercel كـ webhook اختياري. يرسل الخادم `X-Mido-Signature` كتوقيع HMAC-SHA256 لجسم JSON كما أُرسل، و`Idempotency-Key` بقيمة كود الطلب. يجب على المستقبل التحقق من التوقيع باستخدام `EXTERNAL_SYNC_SECRET` وتخزين المفتاح لمنع تكرار الإشعار. فشل الإشعار الخارجي لا يحذف الطلب من SQLite.
- تستخدم صفحة API والربط (`/api`) توثيقاً عملياً للمسارات. المسارات الخارجية محمية بمفتاح المزامنة أو رمز الإدارة.
- حدّث قواعد Firestore من `firestore.rules` عند استخدام مزامنة الكتالوج والحذف. إنشاء الطلبات العامة من المتصفح معطّل؛ الخادم هو مصدر التسجيل.

## الإعدادات

راجع `.env.example` للإعدادات المتاحة:

- `DATABASE_PATH` و`UPLOAD_DIR`: مسارات التخزين الدائم.
- `ADMIN_TOKEN`: رمز اختياري للإدارة. اتركه فارغاً لاستخدام كلمة مرور أول تشغيل.
- `ADMIN_SESSION_SECRET`: سر ثابت لتوقيع جلسات الإدارة.
- `EXTERNAL_ADMIN_WEBHOOK_URL` و`EXTERNAL_SYNC_SECRET`: ربط الإشعارات باللوحة الخارجية.
- تتضمن لوحة الخدمات محرراً لنصوص الصفحة الرئيسية وصورها وبطاقات الأقسام والعنوان. يجب أن تتطابق قيمة `EXTERNAL_SYNC_SECRET` هنا مع `MIDO_SYNC_SECRET` في لوحة الخدمات، وإلا فلن تعمل المزامنة الخارجية.
- تتطلب لوحة الخدمات تسجيل الدخول بحساب إدارة المتجر الموثق قبل استخدام المزامنة. يقبل خادم الخدمات النطاق الافتراضي `mido-web-site.vercel.app`؛ أضف أي نطاق متجر مخصص إلى `MIDO_STOREFRONT_ALLOWED_HOSTS` في بيئة لوحة الخدمات.
- `SEED_DEMO_CATALOG`: لا تضبطه على `true` إلا لبيئة عرض؛ المنتجات التجريبية غير منشورة.

لا تضع ملف `.env` أو قاعدة البيانات أو صور العملاء ضمن مستودع عام. صور كشف النظر تُحفظ في بيانات الطلب وليست ضمن مسار الملفات العامة.

## التحقق في CI

يعمل GitHub Actions على Node.js 22 وينفذ `npm ci` ثم فحص TypeScript (`npm run lint`) وبناء Vite (`npm run build`). لا يشغّل مسار CI مجموعة اختبارات.
